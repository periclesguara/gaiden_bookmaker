# PrintBook platform-template contract

Status: normative implementation contract for future PrintBook work.

Last verified against official platform documentation: 2026-11-16.

## Purpose and scope

PrintBook must not treat a cover template as portable between publishing
platforms. IngramSpark, Amazon KDP, and UICLAP use different template sources,
bleed and safety rules, barcode areas, and final upload formats.

The current default branch does not yet contain the local PrintBook module.
Apply this contract when that module is introduced or changed. Keep generated
interiors, covers, templates containing title data, and operator uploads outside
Git, as required by the repository artifact policy.

## Common domain model

Implement a platform-independent geometry object and one strict adapter per
platform:

- `ingramspark`;
- `amazon_kdp`;
- `uiclap`.

The immutable inputs to a generated cover must include:

- platform profile and profile-version date;
- SHA-256 of the final interior file;
- trim width and height with explicit units;
- final page count;
- binding, paper, and interior color/type;
- reading direction;
- ISBN/barcode mode;
- finish and flap configuration, when applicable;
- template source format and source provenance.

Changing the interior hash, page count, trim, paper, binding, reading direction,
ISBN mode, finish, or platform invalidates every derived template and cover.
Do not silently reinterpret a template from another platform. Validation must
fail closed and explain which input no longer matches.

Store generated files in configured external storage. Persist only metadata,
hashes, validation results, and storage references in the application database.

## IngramSpark profile

### Accepted sources and outputs

- Accept `.idml` and `.pdf` cover templates generated by IngramSpark.
- Do not require, generate, or advertise `.indd`. Effective November 2026,
  IDML is the only delivered InDesign format and INDD is no longer available.
- Treat IDML as an editable template source, never as the final upload.
- Produce two final print files: one complete interior PDF and one complete
  cover PDF.
- The cover PDF contains back cover, spine, front cover, and flaps when
  applicable.

### Validation rules

Use the exact IngramSpark template generated for the selected trim, paper,
interior type, binding, page count, ISBN, and duplex/finish choices.

For the cover profile, validate at minimum:

- 300 ppi effective image resolution;
- CMYK color space;
- 0.125 inch / 3 mm bleed on ordinary covers;
- 0.625 inch / 16 mm wrap for case-laminate covers;
- 0.25 inch / 6 mm type-safety margin;
- mandatory, unscaled barcode placement from the platform template;
- no visible template instruction colors or guide artwork in the final PDF.

The operator UI must display **IDML or PDF accepted** and
**INDD unavailable/deprecated** when IngramSpark is selected.

Official references:

- [IngramSpark Cover Template Generator](https://myaccount.ingramspark.com/Portal/Tools/CoverTemplateGenerator?channel=Organic)
- [IngramSpark File Creation Guide](https://www.ingramspark.com/hubfs/downloads/file-creation-guide.pdf)
- [IngramSpark cover requirements](https://www.ingramspark.com/master-your-book-cover-design)

## Amazon KDP profile

### Compatibility decision

An IngramSpark IDML file is **not** an Amazon KDP template or upload format.
Amazon's cover calculator supplies PDF and PNG guide templates. The same
internal geometry abstraction may be reused, but the KDP cover must be
regenerated against the KDP-specific profile.

Artwork originating in an IngramSpark IDML file may be imported only as a
design source. It must be re-laid on the KDP-generated template and pass all KDP
validations. Never label an IngramSpark template or final cover as directly
portable to KDP.

### Accepted sources and outputs

- Accept KDP calculator `.pdf` or `.png` files as guide templates.
- Produce one final cover PDF containing back cover, spine, and front cover.
- Keep the interior as a separate file; use PDF whenever the interior has bleed.

### Validation rules

Validate at minimum:

- 0.125 inch / 3.2 mm bleed on the top, bottom, and outside edges;
- 300 DPI minimum image resolution;
- embedded fonts;
- flattened transparencies and layers;
- no crop marks, color bars, template text, passwords, or encryption;
- spine text only when the interior has at least 79 pages. A conservative UI
  may require 80 pages to align with KDP Cover Creator.

The operator UI must disable IDML as a KDP platform template and enable PDF/PNG
guide-template input.

Official references:

- [KDP cover calculator and templates](https://kdp.amazon.com/cover-templates?language=en_US)
- [KDP paperback-cover requirements](https://kdp.amazon.com/pt_BR/help/topic/G201953020)
- [KDP print-manuscript file requirements](https://kdp.amazon.com/pt_BR/help/topic/G202145060)

## UICLAP profile

### Interior-first workflow

The final interior PDF is the canonical source for page count and trim
validation. Generate or request the UICLAP cover template only after the
interior is final. A change to the interior, page count, paper, trim, binding,
ISBN mode, or flap configuration invalidates the cover.

### Accepted sources and outputs

- Final interior upload: PDF, maximum 150 MB.
- Final cover upload: JPG, maximum 50 MB.
- Do not send a cover PDF as the final UICLAP cover.
- A design PDF may exist as an intermediate artifact only. Conversion to JPG
  must preserve calculated dimensions and effective resolution.
- The cover image must contain back cover, spine, front cover, and flaps when
  configured, with a maximum total width of 63 cm.

### Validation rules

Validate at minimum:

- 5 mm bleed;
- 10 mm minimum internal safety margin;
- 300 DPI minimum effective resolution, with 600 DPI preferred;
- reserved barcode area of 7 x 2 cm;
- reserved barcode-plus-ISBN area of 7 x 5 cm when ISBN is present;
- barcode area positioned 1 cm above the bottom and 1 cm to the left of the
  spine fold or staple fold;
- final file extension, MIME type, dimensions, orientation, and byte size.

The operator UI must label PDF as **interior/final or cover/intermediate** and
JPG as **final cover**. It must not describe a cover PDF as directly
uploadable to UICLAP.

Official references:

- [UICLAP accepted files and limits](https://suporte.uiclap.com/support/solutions/articles/67000453406-quais-os-tipos-de-arquivos-aceitos-qual-o-tamanho-m%C3%A1ximo-permitido-)
- [UICLAP margins and bleed](https://suporte.uiclap.com/support/solutions/articles/67000747527-margens-sangrias-e-o-caminho-para-uma-impress%C3%A3o-perfeita)

## Operator workflow and manifest

For every generated cover, persist a manifest equivalent to:

```json
{
  "platform": "ingramspark | amazon_kdp | uiclap",
  "profile_version": "YYYY-MM-DD",
  "interior_sha256": "<sha256>",
  "trim": {"width": 0, "height": 0, "unit": "mm"},
  "page_count": 0,
  "binding": "<binding>",
  "paper": "<paper>",
  "interior_type": "<type>",
  "reading_direction": "ltr | rtl",
  "isbn_mode": "<mode>",
  "template": {
    "format": "idml | pdf | png",
    "source": "<platform-generated provenance>",
    "sha256": "<sha256>"
  },
  "output": {
    "format": "pdf | jpg",
    "storage_ref": "<external-storage reference>",
    "sha256": "<sha256>"
  },
  "validation": {
    "status": "passed | failed",
    "checked_at": "<ISO-8601>"
  }
}
```

Do not make a failed or stale artifact available as publication-ready. Display
the profile, source provenance, validation date, and invalidation reason to the
operator.

## Required acceptance tests

Implementation is incomplete without deterministic, offline tests that prove:

1. Selecting IngramSpark accepts IDML/PDF template sources, rejects INDD, and
   exports separate cover/interior PDFs.
2. Selecting KDP accepts PDF/PNG guides, rejects IDML as a platform template,
   and exports a single complete cover PDF.
3. Selecting UICLAP requires a final interior PDF before cover generation and
   exports the final cover as JPG, not PDF.
4. Every platform rejects a template whose page count, trim, paper, binding, or
   ISBN mode differs from the current book.
5. Changing the interior hash or any geometry input invalidates all derived
   outputs.
6. Bleed, safety, resolution, output-format, byte-size, and barcode-area checks
   follow the selected profile.
7. The same book creates three distinct manifests and artifacts rather than one
   ambiguously shared template.
8. Tests use fixtures and mocks only; they do not call publishing platforms or
   upload real operator files.
